Sunday Review is a reflection and follow-through view, separate from Clusters' open category browser. It connects earlier intentions to later action, recognises recorded effort, gives lived experiences value without turning them into work, and offers grounded learning and one direction for the week ahead. Category/tag cards and the old editorial narrative are removed.

Each insight has a useful takeaway and source ids. Its factual explanation and original entries stay behind an expandable source button. At least one source must fall inside the selected period; older entries provide context. A review with recorded completed milestones cannot omit all of them. Future plans cannot count as completed achievements, absent records cannot prove failure, and an idea does not automatically become an obligation. Source ids are validated against the supplied ledger.

The AI reviews up to 300 representative entries, prioritising tracked plans, wishes and the selected window, with earlier entries for context. Results are cached by ledger content, period, local date and timezone, and concurrent requests share work. If the provider is unavailable, the UI shows an honest unavailable state and keeps factual plans/countdowns accessible rather than fabricating an editorial fallback.

Intention plans are optional. A person can set a date, funding target, money set aside, one next step and an active/completed/paused/released state. Amounts come from user input, not guessed product prices or inferred bank balances. Unknown amounts remain unknown. Monetary progress measures a self-reported funding target, not whether a purchase or experience has happened. A date is required for an individual deadline countdown; the app-wide year clock does not make every wish due at year end.

Plans persist through `PATCH /api/intentions` as versioned `review_state` metadata inside the existing `calendar_action` JSONB document. This avoids a new database migration while retaining scheduling fields. The endpoint conditionally updates the previous JSON document and retries concurrent changes. Normalisation exposes the plan independently and preserves it on non-calendar entries; plan metadata never activates Calendar and AI extraction cannot author it. Calendar status and event ids remain unchanged. A future dedicated intentions table can replace this adapter without changing the UI contract.

The app-wide intentions strip shows time remaining and a relevant plan or wish. Sunday Review surfaces a small number of intentions first; the remainder can wait in a collapsed section. Paused, completed and released intentions leave the active list. A saved reflection becomes a normal ledger note, giving later reviews actual new evidence rather than a one-off generated page.

`npm test` covers source grounding, progress coverage, chronology, wish fulfilment, separate ambitions, unsupported deadlines, manual status, date rollover, unknown savings, plan normalisation and validation. `npm run test:review` checks a real model with synthetic source entries and makes no database or Calendar changes. Browser checks cover desktop/mobile layout, expandable evidence, planning controls and funding gaps. A temporary isolated database fixture verified that plan data survives API reloads and does not create a calendar action; it was removed and all original rows were verified unchanged.
