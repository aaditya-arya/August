The three ingestion endpoints (`/api/notes`, `/api/import/keep`, `/api/share-target`) share `ingestion-core.ts` and its Supabase adapter. Extraction and bounded concurrent embeddings finish before creating a raw note. Failed item inserts remove only the raw note created by that request, with cascading cleanup. A submission key maps to a stable note UUID; retries reuse completed items. The composer retains that key alongside an unsaved draft, imports derive it from source content, and native shares keep it in a browser bridge until saving succeeds. Import responses report partial failures, and retries skip successful notes.

Calendar writes persist `google_event_id` and `synced` or `failed` status. Google event IDs are deterministic per extracted item, so a repeated creation request can recover an existing event after a lost response. Manual add controls are hidden for synced and pending items. Imported notes remain available for manual scheduling.

Google OAuth now verifies a short-lived, HttpOnly state cookie before exchanging any code. Access and refresh tokens use encrypted, authenticated, HttpOnly session cookies rather than local files, which supports serverless hosts and isolates browser sessions. Set `CALENDAR_TOKEN_SECRET` to a stable secret, or the existing `GOOGLE_CLIENT_SECRET` is used. Existing users must reconnect once because `.calendar_token.json` is no longer read. `GOOGLE_REFRESH_TOKEN` remains an optional deployment default; disconnecting sets a session tombstone to override that default.

Native share forms first resolve the receiving browser's timezone, then submit JSON with the original reference time and a stable submission key. The bridge safely escapes shared text and restricts scripts with a nonce-based CSP. It retains the shared payload if saving fails.

Gemini has bounded backoff retries on transient errors. `GEMINI_MODEL` optionally overrides the preferred model; `GEMINI_FALLBACK_MODEL` optionally overrides the default `gemini-3.5-flash-lite` fallback. The configured API's model listing includes `gemini-3.8-flash`; Google lists 2.5 Flash as retired, so 2.5 is not the new fallback. See [Google's lifecycle table](https://ai.google.dev/gemini-api/docs/deprecations).

Graph writes request nearby vectors through the existing `match_similar_nodes` RPC, tag-filtered neighbors, and incident semantic edges. They do not download the full ledger or all graph edges per note. Pruning plans every eviction needed at both endpoints. Full graph reads paginate metadata without embeddings, and recomputation is explicit. The UI and server share the 0.62 threshold. `supabase_schema.sql` also includes an optional GIN index on tags for larger deployments; apply the `idx_extracted_items_tags` index statement in the database when deploying that optimization. No new tables or columns are required for these changes.

Run `npm run lint` and `npm run build` for repository checks. `npm run test:ai` checks classification against the real configured Gemini account without saving notes or creating calendar events.
