The three ingestion endpoints (`/api/notes`, `/api/import/keep`, `/api/share-target`) share `ingestion-core.ts` and its Supabase adapter. Extraction and bounded concurrent embeddings finish before creating a raw note. Failed item inserts remove only the raw note created by that request, with cascading cleanup. A submission key maps to a stable note UUID; retries reuse completed items. The composer retains that key alongside an unsaved draft, imports derive it from source content, and native shares keep it in a browser bridge until saving succeeds. Import responses report partial failures, and retries skip successful notes.

Calendar writes persist `google_event_id` and `synced` or `failed` status. Google event IDs are deterministic per extracted item, so a repeated creation request can recover an existing event after a lost response. Manual add controls are hidden for synced and pending items. Imported notes remain available for manual scheduling.

Google OAuth now verifies a short-lived, HttpOnly state cookie before exchanging any code. Access and refresh tokens use encrypted, authenticated, account-bound HttpOnly session cookies rather than local files, which supports serverless hosts and isolates browser sessions. Set `CALENDAR_TOKEN_SECRET` to a stable secret, or the existing `GOOGLE_CLIENT_SECRET` is used. Existing users must reconnect once because `.calendar_token.json` is no longer read. No shared server refresh token is used.

Native share forms first resolve the receiving browser's timezone, then submit JSON with the original reference time and a stable submission key. The bridge safely escapes shared text and restricts scripts with a nonce-based CSP. It retains the shared payload if saving fails.

Gemini extraction tries `gemini-3.5-flash-lite`, then `gemini-3.1-flash-lite`, followed by distinct Flash fallbacks. `GEMINI_MODEL` and `GEMINI_FALLBACK_MODEL` can override the first two choices. Reviews also prefer these Lite models, which passed the source-backed review checks without depending on the configured account's exhausted larger-model daily quota. Set `GEMINI_REVIEW_MODEL` to opt into a larger model independently. Explicit model names avoid retrying an alias and its underlying model as if they had separate quotas. Model access and quota still depend on the configured Gemini project.

Each model gets one SDK attempt with a maximum 45-second timeout per request. A 180-second shared AI deadline covers extraction chunks, their boundary audits, and new-category validation. Reviews share a 150-second deadline across their focus and supporting reflection calls. These limits leave time for the rest of the 300-second server request. Non-Lite Gemini 3 Flash generation requests use LOW thinking. Provider errors move to a different model, and an exhausted deadline returns a retryable failure while preserving the draft.

Overlapping opening and closing quotes are accepted only when both are exact and unique and the closing quote reaches the end of the opening quote. The stored passage is reconstructed from the original note. Changed, ambiguous, reversed, truncated, or duplicated passages are still rejected. Cancelled appointments are classified as unscheduled daily life rather than actionable events.

The account-scoped `/api/tasks` endpoint reads current task state and saves edits by conditionally replacing the previous metadata. Repeating a completion request sends the same desired state, so a repeated tap cannot reopen a task. A title or deadline edit based on an older version receives a conflict rather than overwriting a newer edit. The app refreshes review data after task changes and discards stale reads that could undo a newer completion. Android verifies the account, deadline, and completion state before notifying and records delivered reminders to avoid duplicates. If the network is unavailable at delivery time, the reminder uses the last cached state.

The Android app and widget open the same quick-add form. `POST /api/tasks` saves the user-entered task through the existing idempotent note and item storage. This path needs no AI, embedding, or Calendar request. A successful response updates the account cache and widget immediately. Repeating the same submission after a lost response reuses the saved task.

The widget opens its own short-lived quick-add window. The regular journal still uses `POST /api/notes` for Gemini extraction, source validation, and persistence. The response includes the actual stored tasks and events, which Android uses to show the save summary and refresh its account cache before the next task-list request finishes. Reminder jobs validate the kind as well as the deadline to prevent old task deadline alerts from firing after an item is recognized as a reminder.

Graph writes request nearby vectors through the existing `match_similar_nodes` RPC, tag-filtered neighbors, and incident semantic edges. They do not download the full ledger or all graph edges per note. Pruning plans every eviction needed at both endpoints. Full graph reads paginate metadata without embeddings, and recomputation is explicit. The UI and server share the 0.62 threshold. `supabase_schema.sql` also includes an optional GIN index on tags for larger deployments; apply the `idx_extracted_items_tags` index statement in the database when deploying that optimization. No new tables or columns are required for these changes.
